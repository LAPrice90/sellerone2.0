## POTENTIAL STALE-RISK AREAS

- `out/product_db_preview.csv` is written by many scripts (`A001`, `A002`, `A003`, `A004`, `B001`, `B002`, `B003`) and also used as a local authority by B, D, H, and one-off rebuilds. This is a strong stale-risk layer because local CSV freshness depends on whichever script last dumped the sheet.
- `out/inbound_shipment_contents.csv` has three writers (`B030`, `B031`, `C009`) that represent the same logical entity using different acquisition paths. That is a clear duplicate-source risk.
- `out/fx_rates_daily.csv` has two writers (`B002`, `B006`) and many readers. If either writer runs with different windows or fallback providers, downstream FX results can diverge.
- `out/token_ledger_live.csv` and `out/token_allocations_live.csv` are both multi-writer and physically duplicated by compat mirroring to `out/systems/B/live/...`. Writers include normal B-cycle scripts, export/sync scripts, and one-off rebuild/backfill scripts. This is one of the highest stale-risk areas in the repo.
- `scripts/core/out_paths.py` creates two physical locations for the same logical H and B live files. If one script reads the live path and another reads the legacy path, silent divergence is possible.
- `out/orders_all.csv` and `out/order_items_all.csv` are mostly daily-cycle outputs but also have one-off backfill appenders (`T019`). That creates stale-risk if backfills bypass the normal cycle order.
- `out/inventory_summaries.csv` appears to be produced by both API collection and A-flow inventory publishing, then consumed by B, D, E, and H. Competing refresh timings can make pricing and token logic disagree.
- Listing snapshot families (`out/listing_offer_snapshot_*.csv`, `out/listing_offer_seller_snapshot_*.csv`) are date-based and read by H flows through “latest file” logic. This can become stale if the most recent matching file is not from the intended run window.
- Sellerboard comparison relies on a manual file found by fallback search across `out/analysis_reports` and `reference`. That is a stale-risk because the active comparison input is path-discovery based, not a single authoritative filename.
- H phase1 uses both `data/...` files and `out/...` files for closely related pricing context (`data/offer_snapshot_facts.csv`, `data/sku_daily_intel.csv`, `out/phase1_*`, listing snapshot families). This is a likely stale boundary if refresh cadence differs between `data` and `out`.
