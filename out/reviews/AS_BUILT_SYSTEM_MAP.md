# AS-BUILT SYSTEM MAP

## A) Entrypoints and orchestration
- `run_A_all.bat` launches `scripts/run_A_all.py` (manual launcher present; no scheduler file in repo root) and passes control directly to `main()` in `scripts/run_A_all.py`.
- `run_B_cycle.bat` launches `scripts/run_B_cycle.py`, which is a continuous loop orchestrator in `scripts/run_B_cycle.py` via `main()` -> `_main_loop()`.
- `run_E_all.bat` launches `scripts/run_E_cycle.py`, which executes E tasks in `TASKS` and optionally publishes in `scripts/E010_publish_e_outputs.py`.
- `run_H_cycle.bat` validates `config/pilot_sku.yaml`, then loops `scripts/run_H_pricing_cycle.py --phase1-pilot --phase1-config ...` with restart logic and optional `H_RUN_ONCE` handling.
- `run_30day_catchup.bat` launches `scripts/run_30day_catchup.py` for one-time backfill flow (`B001` -> `B002` -> `B003` -> `B005` -> `B004`).
- `run_api_collection.py` is a direct Python entrypoint (`if __name__ == "__main__"`) that runs `run_api_collection()` and dataset collectors.
- `scripts/run_C_cycle.py` exists as a callable cycle entrypoint (`main()`), but no top-level `.bat` launcher was found outside `scripts/` for C (`UNKNOWN` whether externally scheduled).
- CLI parsing is implemented in `scripts/run_H_pricing_cycle.py` (`_parse_cli_args`), `scripts/A015_build_system_health_check.py` (`_build_arg_parser`), `scripts/A016_refresh_phase1_daily_intel.py` (`argparse` in `main()`), and `scripts/H110_run_phase1_h_pilot.py` (`argparse` in `main()`).
- No repo-level `Makefile` or non-reference `.sh` launchers were found in root launcher set (`run_A_all.bat`, `run_B_cycle.bat`, `run_E_all.bat`, `run_H_cycle.bat`, `run_30day_catchup.bat`) (`UNKNOWN` external Task Scheduler/cron configuration).

## B) Execution graph (text)
- `run_A_all.bat` -> `scripts/run_A_all.py:main()` -> maintenance handshake (`_request_maintenance`, `_wait_for_b_maintenance_ready`, `_activate_maintenance`) -> iterate `RUN_ORDER` with `subprocess.run(...)` for `A001/A002/A003/A010/A005/A004/A016/dedupe/sync/run_E_cycle/A020/process_stock_receipts/A015` in `scripts/run_A_all.py`.
- Inside `scripts/run_A_all.py`, `A015` is handled by mode-aware gate functions (`_run_a015_global_gate`, `_run_a015_profile_a`, `_run_a015_with_freshness`) and may trigger repair call `scripts/B004_build_order_master.py` before re-check.
- `run_B_cycle.bat` -> `scripts/run_B_cycle.py:main()` -> `_main_loop()` -> per-cycle `RUN_ORDER` (`B001/B002/B030/B007/B025/B004/B011`) via `_run_with_retries(...)` -> optional API datasets (`_run_listing_offer_collection_if_due`, `_run_refund_collection_if_due`) -> quiet-mode publish (`B004` + `D001`) -> end-of-cycle health in `_run_health_check_end_of_cycle`.
- `scripts/run_B_cycle.py` invokes `run_api_collection.py` with `API_COLLECTION_DATASETS=listing_offer` or `refunds_adjustments` at call sites `_run_listing_offer_collection_if_due` and `_run_refund_collection_if_due`.
- `run_E_all.bat` -> `scripts/run_E_cycle.py:main()` -> run `TASKS` (`E001/E002/E003/E004/E005`) -> if `E_WRITE_SHEETS=1`, run `_run_a015_profile_e()` gate -> optionally run `scripts/E010_publish_e_outputs.py`.
- `run_H_cycle.bat` -> `scripts/run_H_pricing_cycle.py:main()` in `--phase1-pilot` mode -> `_refresh_offer_snapshots` -> daily alignment via `_run_phase1_daily_intel_alignment_subprocess` (calls `scripts/A016_refresh_phase1_daily_intel.py`) -> split gate via `_resolve_h_split_gate` -> pilot step via `_run_phase1_pilot_subprocess` (calls `scripts/H110_run_phase1_h_pilot.py`) -> `_write_phase1_runtime_floor_snapshot` -> loop sleep.
- `scripts/H110_run_phase1_h_pilot.py` -> `_run_once(...)` -> target universe via `resolve_target_universe(...)` -> per-SKU execution via `_run_for_sku(...)` -> calls `phase1_main_loop.run_a_cycle(...)` and `phase1_main_loop.run_h_cycle(...)` -> optional write via `patch_listings_item_price(...)`.
- `run_api_collection.py:run_api_collection()` -> `acquire_spapi_lock(...)` -> dataset dispatch from `_parse_datasets()` to `_collect_listing_offer_snapshot`, `_collect_inventory_and_inbound`, `_collect_refunds_adjustments` -> `_append_api_run_log(...)` -> `release_spapi_lock()`.
- `scripts/H001_capture_offer_snapshot.py:main()` is a compatibility wrapper that imports `run_listing_offer_collection` from `run_api_collection.py` and runs only listing dataset collection.
- `scripts/run_C_cycle.py:main()` runs C pipeline (`C007/C008/C009/C001/C002/C003/C004/C005/C006`) then `A015` then `C010_publish_c_outputs.py`, with publish behavior controlled by `C_SKIP_PUBLISH` and `C_PUBLISH_ALLOW_WARN`.

## C) Data and state inventory
- Health checklist state: `out/system_health_checklist.csv` is written by `scripts/A015_build_system_health_check.py` and read/gated by `scripts/run_A_all.py`, `scripts/run_B_cycle.py`, and `scripts/run_C_cycle.py`; split profiles are written under `out/cycle_alerts/checklist_*.csv` by `scripts/A015_build_system_health_check.py`.
- Cycle locks and maintenance flags: `out/run_cycle.lock` (`scripts/run_A_all.py`, `scripts/run_C_cycle.py`), `out/B_cycle.lock` (`scripts/run_B_cycle.py`), `out/H_pricing_cycle.lock` (`scripts/run_H_pricing_cycle.py`), and maintenance flags in `out/locks/*` (`scripts/run_A_all.py`, `scripts/run_B_cycle.py`).
- B/H/E run logs: `out/B_cycle.log` (`scripts/run_B_cycle.py`), `out/H_pricing_cycle.log` and `out/H_cycle.log` (`scripts/run_H_pricing_cycle.py`), `out/e_run_log.jsonl` (`scripts/run_E_cycle.py`), and `out/e_decision_log.csv` header-managed by `_ensure_decision_log()` in `scripts/run_E_cycle.py`.
- SP-API call state: `out/locks/spapi.lock`, `out/api_rate_state.json`, and `out/api_call_log.jsonl` are managed by `scripts/api/spapi_owner.py` (`acquire_spapi_lock`, `save_rate_state`, `append_call_log`).
- API collection snapshots/history: `run_api_collection.py` writes dated snapshots (`out/listing_offer_snapshot_YYYY-MM-DD.csv`, `out/inventory_snapshot_*.csv`, `out/inbound_snapshot_*.csv`, `out/refund_adjustment_snapshot_*.csv`) and cumulative histories (`out/listing_offer_history.csv`, `out/listing_offer_seller_observation_history.csv`, `out/inventory_history.csv`, `out/inbound_history.csv`, `out/refund_adjustment_history.csv`) via `_upsert_history(...)`.
- API collection schema contracts are explicit in `run_api_collection.py` constants (`LISTING_REQUIRED_COLUMNS`, `LISTING_SELLER_REQUIRED_COLUMNS`, `INVENTORY_REQUIRED_COLUMNS`, `INBOUND_REQUIRED_COLUMNS`, `REFUND_ADJUSTMENT_REQUIRED_COLUMNS`).
- Phase 1 tabular state: `scripts/phase1_storage.py` persists CSV tables in `data/*.csv` (for example `data/sku_daily_intel.csv`, `data/execution_log.csv`, `data/decision_log.csv`) with enforced schemas in `PHASE1_TABLE_SCHEMAS` and lock `out/phase1.lock`.
- H cycle operational state: `out/h_pricing_cycle_state.json`, `out/h_executioner_action_log.csv`, `out/h_floor_truth_trace.csv`, `out/phase1_runtime_floor_snapshot_latest.csv`, `out/h_seller_profiles.csv`, `out/h_seller_of_interest.csv`, `out/h_seller_delta_learning.csv` are written/read in `scripts/run_H_pricing_cycle.py`.
- B flow core financial/order state is materialized in `out/*.csv` by `scripts/B001_run_orders_to_sheet.py`, `scripts/B002_run_pending_orders_to_sheet.py`, `scripts/B003_run_financial_events_level3.py`, `scripts/B004_build_order_master.py`, and consumed by `scripts/A015_build_system_health_check.py`.
- Google Sheets writes occur in A/B/E scripts using `gspread` call sites (`gspread.service_account`, `open_by_key`, `worksheet`, `update`, `append_row`, `append_rows`) in files such as `scripts/A001_run_listings_to_sheet.py`, `scripts/A003_run_inventory_to_sheet.py`, `scripts/B001_run_orders_to_sheet.py`, `scripts/B002_run_pending_orders_to_sheet.py`, `scripts/B003_run_financial_events_level3.py`, and `scripts/E010_publish_e_outputs.py`.
- SQLite writes/reads were not found in active scripts by `rg -n "sqlite3\.connect\(" scripts run_api_collection.py` (`UNKNOWN` if any external process writes SQLite).

## D) Config inventory
- Dotenv loading behavior is defined in `scripts/api/get_financial_events.py:load_dotenv_if_missing(...)`: reads `secrets/.env` then `.env`, and only sets keys not already in process env (precedence: process env > first file occurrence).
- H launcher config path comes from `run_H_cycle.bat` (`CFG=%ROOT%config\pilot_sku.yaml`) and is enforced by `scripts/run_H_pricing_cycle.py` (`--phase1-config required with --phase1-pilot` in `_parse_cli_args`).
- Repo config files under `config/` include `f_training_set.csv`, `h_floor_vat_policy.json`, `h_head_boundaries.csv`, `h_lab_cohort.csv`, `h_supervisor_tactical_rules.csv`, `phase1_manual_max_caps.csv`, `phase1_writer_modes.csv`, `pilot_sku.yaml`, `pilot_sku_live_test.yaml` (loaded across `run_api_collection.py`, `scripts/A015_build_system_health_check.py`, `scripts/run_H_pricing_cycle.py`, `scripts/H110_run_phase1_h_pilot.py`, and helpers like `scripts/h_floor_policy.py`).
- A/B/C/E/H orchestration behavior is heavily env-driven in `scripts/run_A_all.py`, `scripts/run_B_cycle.py`, `scripts/run_C_cycle.py`, `scripts/run_E_cycle.py`, and `scripts/run_H_pricing_cycle.py` (for lock paths, split health mode, cadence, retry/backoff, maintenance, publish toggles).
- API collection dataset selection uses `API_COLLECTION_DATASETS` with defaults `listing_offer,inventory_inbound,refunds_adjustments` in `run_api_collection.py:_parse_datasets()`.
- SP-API endpoints default to `SPAPI_BASE_URL=https://sellingpartnerapi-eu.amazon.com` in `scripts/api/get_financial_events.py`, `run_api_collection.py`, and `scripts/run_H_pricing_cycle.py`.
- GSpread credential precedence is env-first in scripts with `get_gspread_client` (`GOOGLE_APPLICATION_CREDENTIALS` fallback to `secrets/sellerone-2-0d3642b951a0.json` in files like `scripts/A001_run_listings_to_sheet.py` and `scripts/E010_publish_e_outputs.py`; `scripts/A004_run_fees_to_sheet.py` hardcodes fallback path).
- Health output path defaults are profile-specific in `scripts/A015_build_system_health_check.py` (`_default_checklist_for_profile`, `_default_alert_state_for_profile`, `_default_health_status_for_profile`) and can be overridden via CLI args.
- Scheduler precedence is `UNKNOWN` because no scheduling metadata file was found beside launchers (`run_A_all.bat`, `run_B_cycle.bat`, `run_E_all.bat`, `run_H_cycle.bat`, `run_30day_catchup.bat`); next inspection target would be deployment/runbook docs outside code (`UNKNOWN`).

## E) Observability
- Structured health artifacts are emitted by `scripts/A015_build_system_health_check.py` into `out/system_health_checklist.csv`, `out/cycle_alerts/checklist_all.csv`, `out/cycle_alerts/checklist_<cycle>.csv`, and `out/cycle_alerts/summary.csv`.
- B cycle emits timestamped operational logs to `out/B_cycle.log` via `_log(...)` in `scripts/run_B_cycle.py`, including retries, health snapshots, and publish decisions.
- H cycle emits line logs to `out/H_pricing_cycle.log` and `out/H_cycle.log` via `_log(...)` in `scripts/run_H_pricing_cycle.py`, including split gate results and per-cycle summaries.
- E cycle emits JSONL run records to `out/e_run_log.jsonl` and ensures a decision log schema in `out/e_decision_log.csv` in `scripts/run_E_cycle.py`.
- API-level observability exists through `out/api_run_log.csv` (`run_api_collection.py`) and `out/api_call_log.jsonl` + `out/api_rate_state.json` (`scripts/api/spapi_owner.py`).
- Split-health shadow comparison state/logs are tracked in `out/cycle_alerts/flow_selftest_compare.csv` and `out/cycle_alerts/flow_selftest_state.json` in `scripts/run_A_all.py`, `scripts/run_B_cycle.py`, `scripts/run_E_cycle.py`; H keeps separate `out/cycle_alerts/split_shadow_compare.csv` and `out/cycle_alerts/split_shadow_state.json` in `scripts/run_H_pricing_cycle.py`.
- Per-step subprocess stdout/stderr is mostly not persisted to dedicated files in `scripts/run_A_all.py`, `scripts/run_B_cycle.py`, `scripts/run_C_cycle.py`, and `scripts/run_E_cycle.py` (except bat-level redirect in `run_H_cycle.bat`), so deterministic replay context is partially missing.
- A single unified cross-cycle run manifest tying A/B/C/E/H run IDs to exact input snapshot versions is not present; each cycle tracks local run IDs separately in `scripts/run_A_all.py`, `scripts/run_B_cycle.py`, `scripts/run_E_cycle.py`, and `scripts/run_H_pricing_cycle.py`.
- Input file fingerprinting (hash/version capture) before writes is `UNKNOWN`/not evident in core orchestrators (`scripts/run_A_all.py`, `scripts/run_B_cycle.py`, `scripts/run_H_pricing_cycle.py`, `run_api_collection.py`), reducing deterministic debug traceability.
