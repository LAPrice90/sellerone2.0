B) Phase 2 (staged writes): make partial writes impossible

You already listed this as pending: “Build outputs locally then publish once complete; prevent partial sheet updates.” That is the spiderweb killer.

Concrete implementation pattern:

Each script writes to a run staging folder:
out/staging/<run_id>/...

Each stage produces:

output CSV(s)

a tiny manifest.json (row counts, timestamps, inputs used)

Only the orchestrator is allowed to publish to Sheets, and only from staging.

Publish is done as a single commit step per tab (or per cycle), not throughout the run.

You already have a version of this idea in B cycle (“quiet publish mode”, publish once at end). Extend that pattern to everything, including A.

C) Phase 3 (data contracts): fail fast on column drift

You called this out: “Fail fast if CSV columns/types change.”

Implement a schema registry (simple, no heavy frameworks required):

For every CSV output you depend on, define:

optional columns

expected types (at least for key columns)

key uniqueness rules (if applicable)

Then enforce it in two places:

at read time (before doing any transforms)

at write time (before publishing)

This aligns with your AGENTS rule: “Any new output file must have a schema check.”

D) Phase 4 (rollback): keep last 3 publishable states

You listed: “Keep last 3 snapshots and restore quickly.”

Engineering-grade approach:

Before publishing, snapshot:

the exact CSVs you’re about to publish

Save:

out/snapshots/<timestamp>_<run_id>/...

Keep only last 3 “green” snapshots.

Provide a restore command that republished from a snapshot (only from a known-good snapshot, never from random local state).

E) Phase 5 (rate-limit handling): centralize retries

You want: “Standard retries with backoff and caps.”

The key is one wrapper used everywhere:

retries only for retryable errors (429, 5xx, transient network)

exponential backoff + jitter

max attempts + max total wait

every retry logs:

endpoint

attempt

wait time

request id (if available)

Do not sprinkle try/except across scripts. Centralize.
